# 04 - Docker Containerization

Learn how to containerize your Go + Mux application.

## Files in This Folder

| File | Purpose | Edit? |
|------|---------|-------|
| `Dockerfile` | Multi-stage Docker build configuration | ✅ You edit |
| `docker-compose.yml` | Orchestrate app + PostgreSQL + Redis | ✅ You edit |
| `.dockerignore` | Exclude files from Docker build context | ✅ You edit |
| `main.go` | Application code | ✅ You edit |
| `go.mod` | Go module definition | ✅ Via `go get` |
| `go.sum` | Dependency checksums | ❌ Auto-generated |

### go.mod vs go.sum

- **go.mod** = Declares dependencies (`require github.com/gorilla/mux v1.8.1`)
- **go.sum** = Contains hashes for verification (auto-generated by Go)
- **How go.sum is referenced**: Go automatically verifies hashes when you run `go build` or `go run`

## How to Build and Run

### Option 1: Docker Build & Run

```bash
cd 04-docker

# Build the Docker image
docker build -t mux-app .

# Run the container
docker run -p 8000:8000 \
  -e PORT=8000 \
  -e ENV=production \
  -e DATABASE_URL="postgres://user:pass@localhost:5432/mydb" \
  mux-app
```

### Option 2: Docker Compose (Recommended)

```bash
cd 04-docker

# Start all services (app + db + redis)
docker-compose up

# Start in background
docker-compose up -d

# View logs
docker-compose logs -f api
docker-compose logs -f db

# Stop all services
docker-compose down

# Stop and remove volumes
docker-compose down -v
```

## Dockerfile Explained

### Multi-Stage Build

```dockerfile
# Stage 1: Build
FROM golang:1.24-alpine AS builder
WORKDIR /app
COPY go.mod go.sum ./
RUN go mod download
COPY . .
RUN CGO_ENABLED=0 GOOS=linux go build -o main .

# Stage 2: Runtime
FROM alpine:3.19
RUN apk --no-cache add ca-certificates
WORKDIR /app
COPY --from=builder /app/main .
EXPOSE 8000
CMD ["./main"]
```

### Why Multi-Stage?

| Aspect | Single Stage | Multi-Stage |
|--------|--------------|-------------|
| Image Size | ~800 MB | ~15 MB |
| Build Tools | Included in final image | Not included |
| Security | Larger attack surface | Minimal |

## docker-compose.yml Explained

### API Service

```yaml
services:
  api:
    build:
      context: .
      dockerfile: Dockerfile
    container_name: mux-api
    ports:
      - "8000:8000"
    environment:
      - PORT=8000
      - ENV=production
      - DATABASE_URL=postgres://user:pass@db:5432/mydb
    depends_on:
      db:
        condition: service_healthy
    networks:
      - app-network
```

**Key Points:**
- `depends_on` ensures DB starts first
- `@db` hostname works because of Docker network
- `condition: service_healthy` waits for DB health check

### PostgreSQL Service

```yaml
services:
  db:
    image: postgres:16-alpine
    container_name: mux-db
    environment:
      POSTGRES_USER: user
      POSTGRES_PASSWORD: password
      POSTGRES_DB: mydb
    ports:
      - "5432:5432"
    volumes:
      - postgres-data:/var/lib/postgresql/data
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U user -d mydb"]
      interval: 10s
      timeout: 5s
      retries: 5
```

### Redis Service

```yaml
services:
  redis:
    image: redis:7-alpine
    container_name: mux-redis
    ports:
      - "6379:6379"
    command: redis-server --appendonly yes
    volumes:
      - redis-data:/data
```

## .dockerignore

```
# Git
.git

# IDE
.idea/
.vscode/

# Build artifacts
main
*.exe

```

**Why Use .dockerignore?**
- Reduces build context size
- Prevents secrets from being baked into image
- Excludes unnecessary files

## Common Commands

```bash
# Build image
docker build -t mux-app .

# Run container
docker run -p 8000:8000 mux-app

# Run with env vars
docker run -p 8000:8000 -e PORT=9000 mux-app

# Interactive shell
docker exec -it mux-api sh

# View logs
docker logs mux-api

# Follow logs
docker logs -f mux-api

# Restart container
docker restart mux-api

# Remove container
docker rm -f mux-api
```

## Docker Compose Commands

```bash
# Start all services
docker-compose up

# Start in background (detached)
docker-compose up -d

# Stop all services
docker-compose down

# Stop and remove volumes (fresh start)
docker-compose down -v

# View running services
docker-compose ps

# View logs
docker-compose logs -f

# Restart a service
docker-compose restart api

# Rebuild and restart
docker-compose up --build

# Scale service
docker-compose up --scale api=3
```

## Health Checks

### Dockerfile Health Check
```dockerfile
HEALTHCHECK --interval=30s --timeout=3s --start-period=5s --retries=3 \
    CMD wget --no-verbose --tries=1 --spider http://localhost:8000/health || exit 1
```

### docker-compose Health Check
```yaml
healthcheck:
  test: ["CMD-SHELL", "pg_isready -U user -d mydb"]
  interval: 10s
  timeout: 5s
  retries: 5
```

## Best Practices

### DO:
- ✅ Use multi-stage builds
- ✅ Use specific base image tags (not `latest`)
- ✅ Run as non-root user
- ✅ Add health checks
- ✅ Use `.dockerignore`
- ✅ Use Docker networks for service communication

### DON'T:
- ❌ Include `.env` files in image
- ❌ Run as root user
- ❌ Use `latest` tag for base images
- ❌ Skip health checks
- ❌ Expose unnecessary ports

---

## Key Takeaways

1. **Multi-stage builds** reduce image size dramatically
2. **docker-compose** orchestrates multiple services
3. **Health checks** ensure services are ready
4. **Docker networks** allow service-to-service communication
5. **Volumes** persist data across container restarts
6. **Non-root user** improves security
7. **`.dockerignore`** prevents secrets from being baked in
